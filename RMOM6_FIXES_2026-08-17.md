## 01 — OBC scaler entries built channels-last

**File:** `scripts/build_rmom6_obc_stats.py`, `patch_bridgescaler`

**Symptom:** all ten OBC keys raise `Number of input variables does not match scaler` on `transform`.

**Cause:** three mismatches in one constructor call.
- `DStandardScalerTensor()` defaults `channels_last=True`, so `set_channel_dim` picks `-1` and the
  transform validates the ring against its along-edge extent (759 north/south, 457 east/west)
  instead of its level count (25). Every interior entry uses `False`.
- `mean_x_`/`var_x_` were numpy arrays; `reshape_to_channels_first` calls `Tensor.view` on them.
- `x_columns_` held variable-name strings; interior entries use positional ints, and
  `extract_x_columns` matches by identity.

**Change:** construct with `channels_last=False`, torch tensors for `mean_x_`/`var_x_`, positional
int `x_columns_`, `_fit=True`, `n_=1`. Mirrors `build_rmom6_scaler.py::_make_scaler`.

**Data artifacts:** the four `ocean_bridgescaler_levelwise_*.json` files in
`/glade/derecho/scratch/ajanney/rmom6_regional/scaler/` had their ten OBC entries each repaired in
place. Originals preserved as `*.bak_preobcfix`.

**Verified:** all ten keys fail `transform` before, all ten pass after.

## 02 — Empty target source group aborts the batch

**File:** `credit/preblock/scaler.py`, `BridgeScalerTransform.forward` / `_drop_empty_sources`

**Symptom:** `AssertionError: Key path 'target -> rMOM6_obc_north' found in 'var_dict' but missing
in 'scalers'`.

**Cause:** OBC rings are declared `dynamic_forcing`, so they have variables under `input` and
nothing under `target`. The dataset still emits the source key there as an empty dict.
`scale_var_dict` asserts on every source key it walks into before consulting the variable list.

**Change:** drop empty source groups before calling `scale_var_dict`, merge the untouched originals
back afterwards. The `data_types is None` and not-`None` branches were unified onto one path in the
same edit.

**Not fixed in the dataset:** the "every source appears under every data type" contract is asserted
by `tests/multi_source_dataset_test.py`; changing it there broke two tests and was reverted.

**Verified:** the two dataset-contract tests still pass.

## 03 — Corner cell has no boundary value

**File:** `credit/preblock/ocean_obc_halo.py`, `_write_ring` / `_extend_to_span`

**Symptom:** `ValueError: OBC ring length 457 does not match target span 458 for lon_end`.

**Cause:** with `corner: lon` the east/west rings own the cell where two edges meet, so the write
span is the padded height (458). The preprocessed east ring covers the interior extent (457). No
boundary file supplies a corner value — a corner is not on either segment.

**Change:** `_extend_to_span` replicate-pads the ring's terminal value into the corner cells it
owns. The length check was moved, not removed: it now validates against the interior span, so a
genuinely malformed ring still raises. At most one cell per end is synthesized.

**Verified:** resolves; a deliberately wrong-length ring still errors.

## 04 — OBC source absent from `target`

**File:** `credit/preblock/ocean_obc_halo.py`, `forward`

**Symptom:** `KeyError: OBC source 'rMOM6_obc_north' not in 'target'`.

**Cause:** the generator sets `data_types: [input, target]` so `y` and `y_pred` share the halo
grid. The block required every OBC source in every listed data type; the rings are input-only.

**Change:** a ring missing from one data type is skipped. `seen_rings` accumulates across data
types; a post-loop check raises if a source appears in none of them.

**Rationale:** listing `target` asks for the target to be padded, not for rings to be written into
it. Those cells are prescribed and `exclude_border` drops them from the loss.

**Verified:** resolves; a source declared in no data type still raises.

## 05 — Loss mask built on the wrong grid

**File:** `credit/trainers/trainer_gen2.py`, `_pad_mask_to_model_grid` / `_get_loss_mask`

**Symptom:** mask `(1, 101, 457, 759)` rejected against `y` `(2, 101, 458, 760)`.

**Cause:** the mask is derived from the raw target, so it comes out at the dataset's grid, one cell
short in each padded direction after `ocean_obc_halo`.

**Second defect, silent:** `exclude_border` was applied to the unpadded mask, zeroing the last
*interior* row and column and leaving the prescribed halo scored. This would not have raised had
the shape check not fired first.

**Change:** `_pad_mask_to_model_grid` pads the mask to `model.image_height`/`image_width` using
`exclude_border` as the pad spec (same `[start, end]` convention as the preblock's
`pad_lat`/`pad_lon`), raising if the two disagree. Order is pad → zero border → `shard_spatial`.

**Verified offline:** mask `(1, 101, 458, 760)`, 49.2% valid, halo zeroed, last interior row kept.

**Verified at scale**, job `7134029.desched1`:
```
Loss mask: excluded border lat=(0, 1) lon=(0, 1) from a 458x760 grid.
Loss mask built from raw targets: 49.2% of 101 channels x 458 x 760 cells are valid.
```

## 06 — Multistep gradient was a sum, logged loss a mean

**File:** `credit/trainers/trainer_gen2.py`, `__init__` (`n_backprop_steps`) / `train_one_epoch`

**Symptom:** none. Silent.

**Cause:** `backward()` runs once per rollout step and accumulates into the same `.grad`, so the
optimizer saw the sum over the rollout while `train_loss` (`logs["loss"] / logs["n_loss"]`)
reported the mean. At `forecast_len: 3` that is a 3× effective learning rate against the singlestep
arm. `grad_max_norm` does not absorb it — see open item 2 below.

**Change:** `loss / (grad_accum_every * self.n_backprop_steps)`.

**Consequence:** changes the effective step size of every multistep run. `learning_rate` must be
re-tuned rather than carried forward.

## 07 — Wet mask zeroed in physical space

**File:** `credit/postblock/ocean_wet_mask.py`

**Symptom:** all four multistep runs reach anomaly correlation ≈ 0 (0.005, 0.0007, −0.002) after
16 epochs, against 0.909 for singlestep on identical data. Loss falls 3–4 orders of magnitude.

**Cause:** `y_processed` is in physical units and is fed back through `normalize → fill_values →
concat`. Multiplying by the mask wrote physical 0, which `normalize` maps to `(0 − μ)/σ`. At step 1
the dataset's land is NaN, which `normalize` passes through and `fill_values` turns into 0 in
*normalized* space. Step 2 of every rollout was therefore structurally unlike step 1 over ~half the
domain.

**Measured** `(0 − μ)/σ` on real scalers:

| path | stats | thetao | so |
|---|---|---|---|
| levelwise | notendency | −17.7 … −4.4 | −2452 … −11.9 |
| levelwise | xi | −1951 … −16.4 | −6.2×10⁵ … −2.3 |
| pointwise | notendency | −2214 … −3.0 | −3.1×10⁵ … −0.06 |
| pointwise | xi | −8.6×10⁴ … −5.3 | −4.7×10⁷ … −0.01 |

Pointwise ranges are over cells with real stats; `_fill_stat` neutralises undefined cells to
`μ=0, σ=1`, where physical 0 maps to 0.

**Change:** `masked_fill_nan` (default `True`) writes NaN instead. `False` restores multiply-by-mask
for a pipeline whose feedback path stays in normalized space. A `halo_pad` argument edge-replicates
the static geometry onto the halo grid.

**Dating:** `ocean_wet_mask.py` modified 2026-08-03 23:41; last multistep job log 2026-08-03 12:47.
No run predating this commit was trained with the fix.

**Verified:** `tests/test_rollout_feedback_consistency.py`, and at scale —
`OceanWetMask: extended static geometry by halo_pad=[[0, 1], [0, 1]] -> (458, 760)`.

## 08 — Masked metrics (new flag, default off)

**Files:** `credit/metrics.py`, `credit/trainers/trainer_gen2.py`

**State before:** `loss.mask_missing_targets: true` is set in all eight `_final` configs, so the
loss is computed over 49.25% of cells. `credit/metrics.py` has no mask, so `acc`/`rmse`/`mse`/`mae`
are computed over 100%. Land is 50.75% of cells and is predicted perfectly by construction
(`fill_values` sets it to a constant 0 in both `y` and `y_pred`).

**Measured** on the carib12 grid (`scripts/diagnose_rmom6_metrics.py`):

| true ocean corr | acc logged | acc masked | mae logged | mae masked | rmse logged | rmse masked |
|---|---|---|---|---|---|---|
| 0.99 | 0.9900 | 0.9900 | 0.0556 | 0.1129 | 0.0981 | 0.1414 |
| 0.90 | 0.8998 | 0.8998 | 0.1758 | 0.3569 | 0.3102 | 0.4475 |
| 0.50 | 0.5006 | 0.5006 | 0.3928 | 0.7974 | 0.6928 | 0.9992 |

`mae` reads ~2.03× optimistic (= 1/0.4925), `rmse` ~1.44× (= 1/√0.4925). `acc` is unaffected: land
sits at the field mean and contributes almost nothing to a centred correlation. Cross-config
comparisons within the grid remain valid — all eight share a land fraction.

**Change:** `loss.mask_metrics` (default `false`, requires `mask_missing_targets`). When on,
metrics are computed over the loss mask. The mask is passed as `**kwargs` so metrics objects
without the parameter are unaffected.

## Open — not addressed in this commit

1. **ξ normalization loss imbalance.** Per-channel std in normalized space is exactly `1/ξ`; MSE
   squares it. `ξ` spans 0.0038–19. Deep thetao/so below 1000 m (14 of 101 channels) carry 99.86%
   of the loss; the 50 velocity channels carry 0.00%. The four `_tendency` arms are not measuring
   what the grid was designed to measure.
2. **`grad_max_norm: dynamic` does no clipping.** Clips to the gradient's own norm; torch clamps the
   coefficient at 1.0. Costs one all-reduce per step. Under DDP the `SUM` all-reduce over 8 ranks
   inflates the threshold by √8.
3. **I/O bound.** 1.70 GB/s aggregate in both singlestep (4.46 GB/iter/rank, 21.0 s) and multistep
   (13.4 GB, 63.0 s). The prognostic zarr is float64 with no compressor, 279 MB/sample, 875 GB.
   First fix is `dtype: float32` + zstd in `preprocess_rmom6.py::_write_zarr`.
4. **2,959 cells (0.034%)** are blanked by the wet mask but have real stats — the mask
   (`zl ≤ deptho & wet`) and the loss mask (`isfinite(y_raw)`) are separate sources of truth that
   agree to 0.03%. Those cells carry real data at step 1 and 0 from step 2 on.
5. **Multistep arms need re-running** with 06 and 07, with `learning_rate` re-tuned.
